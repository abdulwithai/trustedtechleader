01

The challenge

A video channel needs a steady pipeline of topics that move from idea to research, script, visuals, voiceover and publishing.

Teams usually track this in spreadsheets while the writing happens elsewhere, so status drifts, duplicate topics creep in and every channel reinvents its own prompts. Running several channels multiplies the problem: each has its own tracking sheet, storage folder, tone and prompt rules.

02

The solution

Responsibility is split cleanly. The AI assistant does the reasoning and writing, while an MCP server exposes tools that read and write the data layer: a Google Sheet as the pipeline database, Docs for research and scripts, and Drive for assets.

A web research layer gathers search, news and forum material into a brief. Each channel has its own sheet, folder and prompt set, and every tool accepts a channel parameter. A separate local text-to-speech tool runs as a subprocess to produce narration, which is uploaded to Drive and linked in the sheet.

05

Implementation notes

Engineering decisions worth knowing about.

  1. Broad tool surface

    Roughly forty tools over a stdio server let any MCP-capable assistant drive the pipeline.

  2. Layered structure

    Agents orchestrate, and services wrap each Google API and research source.

  3. Sheet as state machine

    Sheet row status doubles as the workflow state, with colour-coding applied by a tool.

  4. Isolated text-to-speech

    TTS runs in a separate virtual environment through a subprocess, with a timeout, because of dependency incompatibility.

  5. Cached research

    Research results are cached with a TTL, and Brave search falls back to a keyless search.

  6. Per-channel auth and logging

    OAuth uses per-channel token files, with structured logging via structlog.
