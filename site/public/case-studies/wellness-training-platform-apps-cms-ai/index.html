What it looks like in use

AI drafts new content, and a person approves it in the admin review queue before members see it.

From an AI draft to content members can use

  1. An editor asks the AI

    They ask the assistant to draft a new lesson, program text or event.

  2. The draft is held back

    Nothing goes live. The change waits in a queue, and deleting is not allowed.

  3. A person looks it over

    An admin opens the review queue and sees exactly what would change.

  4. They approve or reject

    Approve to publish the change, or reject it and nothing is touched.

  5. Members see the new content

    Once approved, the lesson shows up in the member apps.

01

The challenge

A subscription wellness business needs to ship structured programs, lessons, live events and a community to members on iOS, Android and the web, while selling through app stores and a web checkout.

Content teams need to publish and schedule material without developers. Marketing needs landing pages, funnels and lifecycle emails tied to subscription data. Members also expect personalised guidance: a conversational coach with memory of prior sessions, voice interaction, periodic progress reports and reminders, all governed by usage limits and moderation controls.

02

The solution

The platform has one shared backend with separate API surfaces for the member apps, the admin CMS and the web app. Native iOS and Android clients and a Next.js web app consume the member API. A React admin CMS manages programs, lessons, events, products, roles and AI settings.

AI features sit on top: streaming text coaching, a realtime voice agent, document context and member memory. An embedded MCP server lets an AI assistant draft CMS content, which a human approves in a review queue. Automation lives in n8n workflows and static marketing pages published to object storage.

05

Implementation notes

Engineering decisions worth knowing about.

  1. One codebase, partitioned by audience

    A NestJS backend splits member, admin, web and internal surfaces, with a module per feature.

  2. Mixed persistence

    Relational storage via TypeORM with dated migrations, a document store via Mongoose, and Redis-backed BullMQ workers for transcription, content mapping and notifications.

  3. Stripe webhook handling

    Raw-body signature verification, tier access grants, and affiliate attribution carried through checkout metadata.

  4. MCP gateway

    Its own authentication, audit log, draft expiry storage and reference-data tool, bridged to a desktop assistant over stdio.

  5. CRM and ops integrations

    Lifecycle sync of subscriptions to a CRM, Slack audit notifications and wearable data context.

  6. Feature flags and AI usage insights

    System settings and flags control rollout, and usage insights monitor it.

  7. Environment-specific deploys

    Container builds and GitHub Actions cover deploy, CI and security testing, with secrets sourced from a parameter store.

  8. Native in-app purchases

    iOS (Swift) and Android (Kotlin) clients complete purchases against a server-created order, and the backend updates the member's access from the result.
